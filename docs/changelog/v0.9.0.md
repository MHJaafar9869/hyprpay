Tamara ("buy now, pay later") joins the roster as the tenth gateway.

### Added
- **Tamara gateway driver** — a tenth `PaymentGatewayInterface` driver for Tamara's redirect "buy now, pay later" checkout, covering every operation Tamara supports: `createCheckoutSession` (hosted BNPL redirect), `capture` (simplified capture), `refund` (simplified refund), `void`/`reverseAuthorization` (both map to Tamara's single order-cancel — `void` fetches the order total first, `reverseAuthorization` uses the amount on the request), `getTransaction`/`searchTransaction`/`findSuccessfulTransactionByReference` (order and merchant-reference lookups), and `verifyWebhook`. A Tamara-specific `authorise($orderId)` method moves a customer-approved order to `authorised` before capture (the step Tamara requires after the `order_approved` webhook). Every request is authenticated with the merchant Bearer API token, amounts are carried exactly as Tamara's `{amount, currency}` money shape, and provider statuses map onto the canonical `PaymentStatus` via `TamaraOrderStatus`. Register it via `GatewayName::Tamara`; configure it under `gateway.gateways.tamara` (sandbox `api-sandbox.tamara.co` / live `api.tamara.co`, resolved by `test_mode`), and reconcile with `gateway:reconcile:tamara`.
- **Webhook verification via the registered Authorization header** — Tamara does not HMAC/JWT-sign webhooks; it echoes the shared `Authorization` header you register for the webhook URL, so `verifyWebhook` compares it against the configured `webhook_secret` in constant time and parses the `event_type`/`order_id`/status.

### Documentation
- Added a Tamara sample and an operation-support-matrix column (with a note on the redirect → authorise → capture flow) to the gateways guide, listed Tamara across the README, recorded the driver's gotchas in the developer MCP server, and added the `tamara`/`bnpl` package keywords.
