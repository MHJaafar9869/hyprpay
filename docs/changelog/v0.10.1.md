A redesign of the monitoring dashboard, a durable database-backed activity store, and a payment lifecycle view.

### Added
- **Durable database store (now the default)** — the dashboard's activity store gains a `database` driver, selected by `GATEWAY_DASHBOARD_STORE_DRIVER` (default `database`; `cache` and `null` remain). It persists a PII-safe, prefix-configurable schema — `hyprpay_invoices`, `hyprpay_payment_attempts`, `hyprpay_payments`, `hyprpay_webhooks` — via a publishable migration. Writes are best-effort, so recording can never break the payment flow that produced them.
- **`hyprpay:install` command** — publishes the config and dashboard views and, with `--migrate`, runs the payment-store migrations.
- **Payment lifecycle** — `GET /hyprpay/lifecycle` returns a reference's full recorded event timeline (matched by order reference or transaction id). The dashboard surfaces it in a detail drawer with **Summary** and **History** tabs (collapsible per-attempt rows), a **Refresh from gateway** action that reuses `listTransactionsByReference`, and **Copy** / **AI copy** of the timeline.
- **Dashboard visuals** — KPI cards with sparklines and growth-trend indicators, a success-ratio donut, by-gateway and by-status breakdowns, active-gateway cards showing each gateway's payment count and a mini graph, and a sortable, filterable recent-activity table.

### Changed
- **CQRS store seams** — the `PaymentActivityRepository` port is replaced by two focused seams: `RecordsPaymentActivity` (write, backed by per-driver Action classes) and `ReadsPaymentActivity` (read, backed by Query classes). `RecordingPaymentEventListener` and `DashboardData` consume the new seams; the cache and null stores are reimplemented against them.
- **Dashboard theme** — restyled with SF Pro Display and Material Symbols on a dark forest-green palette.

### Documentation
- Documented the three store drivers, the database schema and prefix, and the `hyprpay:install` flow in the `gateway.dashboard.store` config block.
