The monitoring dashboard can now show the gateway exchange behind a payment, so diagnosing a decline no longer means leaving it — and CyberSource, which was almost invisible in the feed, finally reports the legs it actually spends its calls on.

### Added
- **Recorded gateway API responses** — an opt-in `RecordingHttpClient` sits beside `LoggingHttpClient` in the transport stack and captures each call: status, headers and body, together with the request that produced it. The recording listener attaches it to the activity record of the operation that made it, and the payment drawer renders it as a plain HTTP message with copy controls for the URL, the request, the response, or both. Off by default via `GATEWAY_DASHBOARD_API_RESPONSES`; it is the only part of the store that holds a real gateway payload, so turn it on deliberately.
- **`Redactor`** — everything recorded is masked before it is stored, not at render time: truncating in the view would leave the real payload in the database. Credentials, signatures, CVVs and the 3-D Secure cryptogram family are replaced outright. Card numbers keep their last four, which is what an operator reconciles against and the most PCI-DSS permits showing; digits are extracted first, so a value the gateway already masked (`411111XXXXXX1111`) lands on the same four, and anything carrying fewer than four digits is masked rather than partially exposed. A body that will not parse as JSON is replaced wholesale rather than guessed at.
- **`DccRateQuoted`, `PayerAuthenticationSetUp`, `PayerAuthenticationEnrolled`, `PayerAuthenticationValidated`** — a full CyberSource 3-D Secure checkout makes six API calls, but only `charge()` dispatched an event, so the busiest gateway left at most one row in the feed and none at all if the customer dropped before charge. The DCC quote and the three authentication legs now dispatch. Authentication legs record as `Pending` rather than `Authorized` — they move no money, so a successful leg leaves the payment in flight — and a DCC quote carries no status, because "no rate offered" is a normal outcome rather than a failure.
- **`hyprpay:prune --hours`** — the durable store had no retention at all. The cache driver is a bounded ring buffer that trims itself, but the database driver grew for as long as payments kept happening, and with response recording on each row can carry a request/response pair. Applies a window to the tables that grow, and reports plainly on the drivers that keep no history. Schedule it daily.
- **`PrunesPaymentActivity`** — the third seam beside `RecordsPaymentActivity` and `ReadsPaymentActivity`, implemented per driver.
- **Cursor tailing on the activity feed** — `/activity?after=<sequence>` returns only what has landed since, so a poll that finds nothing new costs an empty array instead of the whole window. Stores with no monotonic position ignore the cursor and callers fall back to replacing, which is the previous behaviour.

### Changed
- **`ReadsPaymentActivity::recent()` takes an optional `$after` cursor.** Source-compatible for callers, but any host implementing the interface must update its signature.
- **The activity feed no longer carries recorded payloads.** `present()` was shared between the drawer and the feed, so every row shipped its request and response bodies to a poll that runs every few seconds. Only `lifecycle()` carries them now — the drawer is the only view that renders them.
- **`GatewayName::label()` shortens CyberSource Unified Checkout to CyberSource UC**, the name already used throughout the guide. Also reaches the reconcile command's output, its only other consumer.
- **The dashboard moves to IBM Plex Sans and JetBrains Mono**, sharing a typeface with the docs site.
- **`payment_attempts` gains an `api_responses` column**, folded into the existing create migration rather than added as a second file, matching the package's one-migration convention. An install that has already migrated needs `migrate:fresh` on those tables to pick it up.

### Fixed
- **The docs header retreats while scrolling down** and returns on the first upward move, at every width; panes pinned beneath it — the action tree, the gateway bar, the changelog index — follow it via `--nav-offset` instead of hovering over the gap it leaves.
- **Landing-page gateway links carry their own gateway.** Every "Read the actions" link and every card in the rest grid pointed at a bare `guide.html`, which always booted to CyberSource. The guide now reads `?gw=` on boot and writes it back when a tab is selected, so a scoped page survives a reload and can be linked to; the query string leaves the existing `#action` anchors free and the two compose.
- **Sections 03 and 04 of the landing page are staged per item** rather than fading in as single blocks — the operation matrix fills in row by row as it crosses the fold, and the install steps ignite in order.
