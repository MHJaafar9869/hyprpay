CyberSource Flex Microform can now carry a billing address, and 3-D Secure now enforces a fully-authenticated ECI — rejecting attempted or unauthenticated results and emitting a domain event so they can be alerted on, recorded, or reviewed.

### Added
- **Microform billing address** — `createMicroformSession` now includes an `orderInformation.billTo` block when the `CheckoutSessionRequest` carries a `billTo` `BillingAddress`, so a Flex Microform capture context can capture the cardholder's billing details for AVS and risk screening. It is omitted when no billing address is supplied, so existing calls are unchanged.
- **`CybersourceEci` value object** — normalises a CyberSource 3-D Secure ECI from a `consumerAuthenticationInformation` block (preferring the network-normalised `eciRaw`, falling back to `eci`, zero-padded) and classifies it as fully authenticated (`02` Mastercard / `05` Visa, American Express, JCB, Diners Club, Discover), attempted (`01` / `06`), or not authenticated (`00` / `07`).
- **`PayerAuthenticationEciRejected` event** — a new PII-safe domain event carrying the gateway, the rejected ECI, the accepted ECIs, the outcome classification, the authentication transaction id, and the normalised `Declined` status. It is dispatched when a completed 3-D Secure result is rejected for a non-authenticated ECI, and is handled by the logging and activity-recording listeners like every other `PaymentEvent`.

### Changed
- **CyberSource 3-D Secure enforces a fully-authenticated ECI.** `enrollPayerAuth` and `validatePayerAuth` now mark a completed authentication unsuccessful — and dispatch `PayerAuthenticationEciRejected` — when its resolved ECI is not `02`/`05`, so an attempted or unauthenticated result never carries a spurious liability shift into the charge. A pending step-up challenge (no final ECI yet) and a response with no ECI at all are unaffected.
- **`CybersourceUnifiedCheckoutGateway` accepts an optional `EventDispatcher`.** A third, nullable constructor argument lets the driver emit `PayerAuthenticationEciRejected` directly; `PaymentGatewayFactory` wires it automatically. Existing two-argument construction keeps working, emitting no event.
