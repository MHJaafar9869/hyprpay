Airwallex joins the SDK as the ninth gateway.

### Added
- **Airwallex gateway** — behind the same `PaymentGatewayInterface`: create a PaymentIntent for the client-side (Elements / drop-in) checkout (`createCheckoutSession` returns the intent id and `client_secret`), capture a manual-capture authorization hold, refund a captured intent, charge a saved card against a stored PaymentConsent (`chargeStoredCredential`), look up an intent for reconciliation, and verify the HMAC-SHA256 webhook signature. Resolve it with `GatewayName::Airwallex`. Amounts are sent as exact major units, and the API-access login token is cached per request.
- `gateway:reconcile:airwallex` reconciliation command and an `airwallex` credentials block (client id, API key, webhook secret, plus optional API version and connected-account id) in the config.

### Documentation
- Airwallex added to the gateways guide (runnable sample + operation matrix), the interactive docs, and the landing page (now nine gateways).
- Noted why the driver exposes `chargeStoredCredential` but no `vaultInstrument` — an Airwallex stored credential is a PaymentConsent created client-side, so the card never reaches the server.
