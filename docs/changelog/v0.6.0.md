A developer MCP server ships with the SDK, and the CyberSource orchestrated flow can now vault the payment credential in TMS.

### Added
- **CyberSource orchestrated-flow token vaulting** — `CheckoutSessionRequest` gains `createToken` and `tokenTypes`. When the Unified Checkout v1 orchestrated (autoProcessing) mandate runs, the widget now vaults the payment credential in the Token Management Service (`completeMandate.tms.tokenCreate` / `tokenTypes`), so the signed result JWT carries reusable customer / payment-instrument / instrument-identifier token ids for later stored-credential charges. Vaulting is off by default (`createToken: false`).
- **Developer MCP server** (in [`mcp/`](../../mcp/)) — a [Model Context Protocol](https://modelcontextprotocol.io) server that lets an AI coding assistant explore the SDK and generate correct integration code. It reflects the live `Hyprpay\Payments\*` classes at call time, so what it reports never drifts from the code, and it is entirely **read-only** — it helps you *write* an integration and never calls a gateway. Six tools: `get_sdk_overview`, `list_gateways` (with each driver's exact supported-operation set, derived from `PaymentGatewayFactory` and `AbstractPaymentGateway`), `get_operation_details`, `get_class_details`, `get_code_template` (a ready-to-adapt snippet with imports included; unsupported gateway/operation pairs are rejected), and `search`. Built on `php-mcp/server` as its own Composer project, so its dependency never touches the SDK's.
- A project-scoped `.mcp.json` at the repository root registers the server (`hyprpay-payments`, stdio, `php mcp/server.php`) for anyone who clones the package; `mcp/README.md` covers setup and global registration. The server is repo tooling and is not part of the Composer package (`composer require hyprpay/payments` does not install it).
