An opt-in monitoring dashboard, served at `/hyprpay`, for watching gateway activity.

### Added
- **Monitoring dashboard (`/hyprpay`)** — an opt-in operator UI, off by default, mounted by `GatewayServiceProvider` when `gateway.dashboard.enabled` is set. It shows each gateway's health straight from config (configured vs not, test vs live, the default), headline stats (recorded operations, success rate) and a live-polling recent-activity feed, plus an on-demand **look-up-by-reference** panel that queries the gateway directly via `listTransactionsByReference` (CyberSource today; other gateways degrade gracefully to an "unsupported" notice). The view is self-contained — inline CSS/JS, no build step, no CDN — and publishable with `php artisan vendor:publish --tag=gateway-dashboard-views`.
- **`PaymentActivityRepository` port + `PaymentActivityRecord`** — a new `Domain\Contract` port that feeds the dashboard's activity feed, alongside a PII-safe `Domain\Result\PaymentActivityRecord` DTO (operation, gateway, normalized status/outcome, correlation ids, amount) that serialises to primitives. The default adapter, `CachePaymentActivityRepository`, is a **bounded cache ring buffer** (no database, no migration) keeping the last `limit` records; a host can bind a durable, database-backed implementation without touching the dashboard. When the store is disabled a `NullPaymentActivityRepository` is bound instead, so the dashboard renders with no activity and zero recording overhead.
- **`RecordingPaymentEventListener`** — mirrors `LoggingPaymentEventListener`: subscribes to the `PaymentEvent` interface and normalises every event into a `PaymentActivityRecord`, capturing only correlation ids, the normalized status/outcome, and the amount — never the raw payload or card data. Registered only when `gateway.dashboard.store.enabled` is set.
- **Telescope-style access control** — every dashboard request must satisfy the `viewHyprpay` authorization gate (defined by the provider, defaulting to the local environment and overridable by the host) **and** pass the configured `gateway.dashboard.middleware` stack (default `['web']`); the `AuthorizeDashboard` middleware is prepended to enforce the gate. The URL prefix is configurable via `gateway.dashboard.path`.
- **`gateway.dashboard` config block** — `enabled`, `path`, `middleware`, and a `store` group (`enabled`, `cache`, `key`, `limit`), each env-backed (`GATEWAY_DASHBOARD`, `GATEWAY_DASHBOARD_PATH`, `GATEWAY_DASHBOARD_STORE`, `GATEWAY_DASHBOARD_LIMIT`, …).

### Changed
- **Composer requirements** — added `illuminate/auth`, `illuminate/cache`, `illuminate/routing`, and `illuminate/view` (the standard Laravel components the dashboard uses); every host Laravel app already provides them.

- Documented enabling the dashboard, the `viewHyprpay` gate override, the middleware/path/store toggles, and the publish tags in the README.
