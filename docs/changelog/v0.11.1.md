Correct how CyberSource 3-D Secure validation references the card.

### Fixed
- **CyberSource 3-D Secure validation card reference** — `validatePayerAuth` now references the card by the transient token's `jti` (`tokenInformation.jti`), which is the only field CyberSource's `POST /risk/v1/authentication-results` token model accepts. It previously sent `tokenInformation.transientTokenJwt`, a field the validate endpoint ignores, so the validation call went out with no card reference. The `jti` is parsed from the transient token exactly as `setupPayerAuth` already does; an unreadable token now carries no reference rather than a field CyberSource discards.
