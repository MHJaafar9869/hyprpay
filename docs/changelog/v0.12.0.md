Issuer installments, cardholder decline messages, and a configurable capture-context endpoint.

### Added
- **Issuer-funded installments** — `ChargeRequest` accepts an optional `Installment` value object (`totalCount`, plus optional `sequence`, `planType`, and `gracePeriodDuration`) that maps to the CyberSource `processingInformation.installment` block, so a charge can be split into issuer-funded installments (common across MENA, LATAM, and Turkey) instead of the merchant splitting it into separate stored-credential charges. Only the fields supplied are sent; a charge without an installment is unchanged.
- **Cardholder decline messages** — `DeclineOutcome::customerMessage()` turns a classified decline into a safe, specific message to show the cardholder — insufficient funds, expired card, failed verification, invalid details, a card that cannot be used, or an issuer decline — without ever leaking a raw processor code. Pair it with the existing `reason` code to localise your own copy and fall back to the message otherwise.
- **Configurable capture-context endpoint** — the Unified Checkout session can be created against `/uc/v1/sessions` instead of the default `/up/v1/capture-contexts` by setting the `capture_context_endpoint` credential (under `extra`) to `sessions`. The default is unchanged, so existing integrations are unaffected.
