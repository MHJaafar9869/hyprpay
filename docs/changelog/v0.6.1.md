The CyberSource Unified Checkout orchestrated result JWT is now read across every envelope CyberSource nests it under, not just `details`.

### Fixed
- **CyberSource orchestrated result-JWT envelope resolution** — `VerifiesResultJwt` resolved the completed-payment response only under a `details` envelope (or the bare top level), so a real Unified Checkout result JWT that nests the response under a `data` or `content` envelope failed amount verification with `missing amount details` even though its signature was valid. Every claim — transaction status, id, order reference, amount/currency, TMS token ids, network transaction id, and card metadata — is now resolved across the `details`, `data`, and `content` envelopes and the bare top level in turn (first non-blank wins), so the orchestrated flow verifies regardless of which shape a given Unified Checkout client version returns. The amount and currency match against the request remains enforced.
