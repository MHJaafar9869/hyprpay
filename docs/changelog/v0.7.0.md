Native Apple Pay / Google Pay charges land on the CyberSource Unified Checkout driver.

### Added
- **Digital-wallet charges (`chargeWallet`)** — a new `PaymentGatewayInterface` operation charges a native Apple Pay / Google Pay token. `WalletChargeRequest` carries a `WalletToken` — either a `DecryptedWalletToken` (the merchant-decrypted network token: DPAN, cryptogram, expiry, optional ECI and card type) or an `EncryptedWalletToken` (the raw device-encrypted token) — plus the `WalletType`, amount, and optional billing / reconciliation / device-fingerprint context. The **CyberSource Unified Checkout** driver supports both CyberSource wallet models (`processingInformation.paymentSolution` `001` Apple Pay / `012` Google Pay): a decrypted token is sent as `paymentInformation.tokenizedCard` with `transactionType` `1` (the canonical in-app wallet path), and an encrypted token is forwarded as `paymentInformation.fluidData` for CyberSource to decrypt. Either way the SDK never decrypts the token or handles the cleartext PAN. This suits a merchant-hosted wallet button (your app runs the wallet's `ApplePaySession`, merchant validation, and domain registration). Every other driver inherits the `UnsupportedOperationException` default until it implements the operation.
- **`WalletCharged` event** — emitted after a wallet charge completes, carrying the `wallet`, `orderReference`, `money`, and `result`, and logged by the built-in `LoggingPaymentEventListener` (wallet type and safe outcome only, never the token).

### Documentation
- Documented `chargeWallet` in the gateways guide (operation matrix plus runnable CyberSource Apple Pay samples for both wallet models) and the `WalletCharged` event in the observability guide.
