Native Apple Pay / Google Pay charges land on the CyberSource Unified Checkout driver.

### Added
- **Digital-wallet charges (`chargeWallet`)** — a new `PaymentGatewayInterface` operation charges a native Apple Pay / Google Pay token. `WalletChargeRequest` carries the wallet's device-encrypted token (`encryptedToken`), the `WalletType` (Apple Pay / Google Pay), the amount, and optional billing / reconciliation / device-fingerprint context. The **CyberSource Unified Checkout** driver implements it by forwarding the encrypted token as `paymentInformation.fluidData` for CyberSource to decrypt and authorize (`processingInformation.paymentSolution` `001` for Apple Pay, `012` for Google Pay) — so the SDK never decrypts the token or handles the cleartext PAN, and carries no Apple Pay crypto or certificates. This suits a merchant-hosted wallet button (your app runs the wallet's `ApplePaySession`, merchant validation, and domain registration) and requires the wallet's payment-processing certificate registered with CyberSource's decryption service. Every other driver inherits the `UnsupportedOperationException` default until it implements the operation.
- **`WalletCharged` event** — emitted after a wallet charge completes, carrying the `wallet`, `orderReference`, `money`, and `result`, and logged by the built-in `LoggingPaymentEventListener` (wallet type and safe outcome only, never the token).

### Documentation
- Documented `chargeWallet` in the gateways guide (operation matrix plus a runnable CyberSource Apple Pay sample) and the `WalletCharged` event in the observability guide.
